# Полный backlog проекта AIOS

Состояние кода: `aios@9b43ead`. Задачи выведены из текущей реализации и целевого состояния,
разбиты до уровня «одна задача — одно изменение, которое можно отдать отдельному исполнителю».
Приоритеты: `critical` (без этого сдача невозможна или числа недостоверны), `high`
(теряем баллы по критериям жюри), `medium`, `low`.

Это единственный список задач по проекту. Обоснование приоритетов — в
[AUDIT_PLAN_2026-09-08.md](AUDIT_PLAN_2026-09-08.md), исходный аудит — в
[8sept-audit/](8sept-audit/).

## Как работать по этому списку

1. Порядок — в разделе [«Порядок выполнения»](#order) в конце документа: пять волн и шесть
   независимых потоков. Внутри потока порядок соблюдать, между потоками можно параллелить.
2. Ветка от `main`, коммит на задачу, сообщение начинается с ID (`SUB-02: …`).
3. Задача сделана только вместе со своим тестом; критерий готовности указан у каждой.
4. Прогонять только те группы тестов, которых касаешься. Полный `pytest` — больше 15 минут и
   требует Docker.
5. Не менять числа и артефакты: `data/`, `config/*.json`, `frontend/public/data/`, `BASE_NPV`.
   Если задача требует их изменить — это отдельная задача из списка, а не побочная правка.
6. Задачи `ORG-*` — не для исполнителя кода: это внешние действия человека.
7. Если задача упирается в отсутствующий артефакт (production-веса, прогон OPM) — пропустить и
   записать причину, а не подставлять правдоподобное значение.
