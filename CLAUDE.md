# AIOS Hackathon — трек 2

Мультиагентная система управления фондом скважин с нейросетевым суррогатом. Модель **Model_Z**: 103 скважины, управление с **01.01.2007**, 225 управляющих шагов при 224 наблюдаемых интервалах. Цель — максимизация ЧДД. Разработка 10.08 — 11.09.2026.

Этот репозиторий — база знаний, не код. Код живёт отдельно.

## Как устроены утверждения

Каждый факт снабжён ссылкой на источник: `[Онб.10]` — слайд онбординга, `[Разр.14]` — страница лекции по разработке, `[Лек.34]` — слайд лекции по DL, `[12.08 35:18]` — таймкод встречи. Проверяется без перечитывания транскрипций.

В `07_concept.md` пометки: **[факт]** — требование организаторов, **[выбор]** — наше инженерное решение, **[гипотеза]** — непроверенная ставка. Различать обязательно.

## Правила работы с этими файлами

- Записывать **только установленное**: факты из материалов, разобранные данные, подтверждённые решения. Идеи, планы и рассуждения — в чат, не в файлы.
- Меняя решение — дописывать строку в журнал `07_concept.md` §9 с причиной. Иначе через неделю тот же спор откроется заново.
- Числа по деку — перепроверять парсингом, а не доверять записанному: `python3 tools/check_deck_facts.py`. Так уже находились ошибки — про `SHUT`, про фонд нагнетательных и про то, что перфорации якобы заданы блоком в начале.
- Сроки в файлы не писать.
- Распределение людей — в `README.md` и `assignments/`, в `context/` его нет. Задачи в `context/09_tasks.md` пронумерованы сквозной нумерацией, `README.md` и `assignments/` ссылаются на неё, а не дублируют.
- `README.md` — вход, а не сводка. Объяснение и навигация в нём, содержание в `context/`. Числа, решения и контракты в README не переписывать: копия разъедется с оригиналом молча.
