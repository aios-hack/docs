## 4. Методика ЧДД — разбор

### Структура расчёта

- Производственные показатели: по скважинам, **месячный шаг**
- Агрегация: по **календарным годам**
- Дисконтирование: **годовое**, WACC = 10%, `DF_y = 1/(1+WACC)^(y−y₀)`, y₀ = 2007
- `ЧДД = Σ_y FCF_y · DF_y`, где `FCF = EBITDA − CAPEX`, `EBITDA = Выручка − OPEX − Отчисления − DR_incl`

Для Model_Z `y₀ = 2007` (год начала управления). К 2025 коэффициент дисконтирования = 1/1.1¹⁸ = **0.18**. Ранняя добыча стоит в 5.5 раза дороже поздней — на длинном горизонте это доминирующий фактор целевой функции.

### Действующий фонд

Скважина действующая, если `WLPR > 0` **или** `WWIR > 0`. Остановленная не считается.

### Нормативы

| Показатель | Значение |
|---|---|
| Цена нефти | 28 000 руб/т |
| Отчисления | 19 600 руб/т нефти |
| OPEX нефть | 40 руб/т |
| OPEX жидкость | 100 руб/т |
| OPEX закачка | 30 руб/м³ |
| Содержание действующего фонда | 1.0 млн руб/скв·год |
| Операция смены ЭЦН | 1.8 млн руб/операцию |
| Остановка или запуск | 1.0 млн руб/событие |
| Перевод под закачку | 5.0 млн + стоимость ЭЦН |
| WACC | 10% |
| Налог на имущество | 2.2% |
| Налог на прибыль | 25% |

### Маржа по нефти

```
28 000 − 19 600 − 40 = 8360 руб/т
```

Отчисления забирают 70% выручки.

### Порог рентабельности по обводнённости

Плотность нефти 833 кг/м³, OPEX жидкости 100 руб, содержание фонда 1 млн руб/скв·год:

```
годовая маржа = q·365·[(1−W)·0.833·8360 − 100] − 1 000 000

q = 100 м³/сут  →  W_безубыточности = 98.2%
q = 20  м³/сут  →  W_безубыточности = 96.6%
```

**Закрывать скважины по обводнённости почти всегда невыгодно.** Эвристика «глушим всё выше 90%» уничтожает ЧДД. Единственная зона, где остановка оправдана — обводнённость выше 97–98% при низком дебите.

### Логика ЭЦН — главная ловушка

Типоразмер подбирается по фактическому `WLPR`. Замена = **1.8 млн OPEX + полная стоимость нового насоса в CAPEX** (0.55–8.05 млн руб).

Справочник (номинал / интервал / стоимость млн руб):

```
15  до 20     0.55      125  100–160   2.75
20  15–30     0.65      160  125–210   3.35
30  20–50     0.75      210  160–250   4.10
50  30–80     0.90      250  210–320   4.75
80  50–100    1.85      320  250–400   6.00
100 80–125    2.30      400  320–500   8.05
```

Правила:
- дебит внутри интервала → замены нет
- превышение верхней границы → минимальный подходящий больший типоразмер
- понижение типоразмера только при падении `WLPR` **более чем на 100 м³/сут ниже** нижней границы текущего интервала
- при перекрытии диапазонов сохраняется установленный насос

**Следствие 1 — храповик.** Для насосов 80/100/125 нижние границы 50/80/100. Понижение требует `WLPR < −20`, `< −20`, `< 0`. Физически недостижимо. **Типоразмер движется только вверх.**

Для Model_Z с её диапазоном `LRAT` 0–110 м³/сут это ещё жёстче: почти весь фонд живёт в типоразмерах 15–125, где ширина интервалов 5–45 м³/сут, а правило понижения требует падения на 100 м³/сут ниже нижней границы. **Понижение типоразмера в Model_Z недостижимо в принципе.** Любой временный разгон скважины фиксирует дорогой насос навсегда.

**Следствие 2 — плавный разгон дороже скачка:**

```
80 → 100 → 125:  (1.8 + 2.30) + (1.8 + 2.75) = 8.65 млн руб
80 → 125       :  1.8 + 2.75                  = 4.55 млн руб
```

Оптимизатор, двигающий `LRAT` помесячно, платит за каждый пересечённый порог. На 103 скважинах × 225 шагов — сотни млн руб на ровном месте. **Штраф за негладкость расписания надо вносить в целевую функцию явно.**

### Прочие событийные затраты

- Остановка/запуск: 1.0 млн за событие. Закрыть и снова открыть = 2.0 млн.
- Перевод под закачку: 5.0 млн + ЭЦН, весь в OPEX, разово. Отдельная стоимость остановки при переводе не начисляется.
- В базовом сценарии Model_Z **30 переводов** ≈ 160–220 млн руб в зависимости от типоразмеров ЭЦН. Момент перевода дисконтируется — сдвиг на 5 лет умножает стоимость на 0.62, но задержка закачки бьёт по поддержанию давления.

### Итог: в чём реальная игра

1. **Вытащить добычу в ранние годы** — дисконт 10% на горизонте 18.7 лет, коэффициент 2025 года всего 0.18
2. Ограничитель — BHP 50 бар на добывающих, 300 бар на нагнетательных
3. **Распределение закачки** против раннего прорыва воды
4. **Не дёргать режимы** — гладкие расписания дешевле рваных, храповик ЭЦН необратим
5. Тайминг переводов под закачку — 30 событий в базе, каждое дискретно и дорого
6. **Отсев малодебитного высокообводнённого фонда** — при типичных для Model_Z 5–30 м³/сут содержание скважины 1 млн руб/год перестаёт окупаться раньше, чем в MODEL_Y

## 5. Интерфейс данных

`_unused_track1/MODEL_Y/USER/MODEL_Y/script_1.py` задаёт готовый контракт выгрузки — по скважине, по месяцу. Скрипт лежит в папке трека 1, но набор величин определяется Методикой ЧДД и потому одинаков для обоих треков:

```
WLPT, WLPR, WOMT, WOMR, WWIR, WWIT, WBP9(THP), WBHP, WEFF
+ производные: WLPT_Diff, WOMT_Diff, WWIT_Diff   (.diff().shift(-1))
```

Методика ЧДД потребляет ровно: `WOMT_Diff`, `WLPT_Diff`, `WWIT_Diff`, `WLPR` + состояние скважины.

### Что это значит для архитектуры

**Суррогату не нужно предсказывать ЧДД.** Он предсказывает дебиты, экономика считается детерминированно и точно:

```
суррогат: управление → 4 канала × 103 скважины × 225 месяцев  (~93k чисел на сценарий)
слой ЧДД: точная реализация методики поверх прогноза
```

Следствия:
- **полнополевые суррогаты (FNO, U-Net, 3D CNN) не нужны вообще** — задача скважинного уровня
- целевой тензор крошечный → требования к объёму обучающих данных резко падают
- ошибка по ЧДД раскладывается на ошибку по дебитам + точную экономику, легко диагностируется

**Ограничение:** логика ЭЦН, остановок и переводов **путезависима и дискретна** → ЧДД кусочно-постоянен по вектору управления. Чистый градиент сквозь `управление → ЧДД` ломается о ступеньки. Правильная схема: градиент/гладкая оптимизация по дебитам + дискретный поиск (CMA-ES, локальный поиск) по событиям.

## 6. Вопросы организаторам — блокирующие

1. **Налоги.** Налог на прибыль 25% и налог на имущество 2.2% есть в справочной таблице, но отсутствуют в формуле `FCF = EBITDA − CAPEX`. Применяются?
2. **`DR_incl`** в формуле EBITDA не определён. Амортизация? Прочие доходы/расходы?
3. **Единицы.** «Q выражается в тыс. м³», при этом `WOMT` — масса (тонны), а цены в руб./т. Формула `Выручка = Q·P/1000` в млн руб. не сходится по размерности (расхождение 1000×). **Нужен эталонный ЧДД базового сценария для калибровки нашей реализации.**
4. **Начальный ЭЦН.** Насос на старте управления (01.01.2007) начисляется в CAPEX или считается уже установленным? Для Model_Z это 103 скважины и потенциально сотни млн руб разницы.
5. **Горизонт.** Управляем до конца дека (09.2025) или тестовый кейс задаёт более короткое окно?
6. **Формат сдачи.** Точная спецификация `wells_schedule.inc`: только `WCONPROD`/`WCONINJE`/`DATES` или ещё `WELOPEN`? Допустимы ли значения `LRAT`/`RATE` вне базовой сетки с шагом 5?
7. **Ресурсы.** Число лицензий tNavigator и допустимая параллельность прогонов. Время прогона известно (~15 мин), квота — нет.

Пункт 3 критичен: если наша реализация ЧДД расходится с эталонной, вся оптимизация идёт по неверной целевой функции.

**Закрыто материалами** (было в этом списке):
- *Время прогона* — ~15 мин на Model_Z [`info/Запись_встречи_12_08_2026`, 35:18]
- *Программа бурения* — в Model_Z фиксирована, `WELLTRACK`/`COMPDATMD` заданы блоком, новых скважин по ходу нет
- *Расширенный набор сценариев* — описание производственной ситуации: ограничение в конкретном году, выпадение скважин, дефицит воды на товарном парке [12.08, 24:25]
