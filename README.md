## Структура репозитория

| Каталог | Что это |
|---|---|
| `context/` | база знаний: контракты, решения, разбор дека и Методики ЧДД, открытые вопросы, требования организаторов, дизайн интерфейса, аудит интерфейса |
| `context/sources/` | сырые транскрипции лекций и встреч — провенанс решений, не документация; читаются по таймкоду, не редактируются |
| `context/tools/` | `check_deck_facts.py` — перепроверка чисел по деку одной командой |
| `models/` | данные организаторов: дек, эталонный расчётчик, методика, ТЗ — подменять запрещено, путь зашит в `aios/conftest.py` |
| `v2/` | текущие задачи (`tasks/`) и их статус (`STATUS.md`) |
| `v2/assignments/` | владение каталогами кода, по карточке на человека |
| `v1/` | архив первой версии — 65 закрытых задач, персональные пакеты, каталог отвергнутых вариантов; открывать только за историей решения ([`v1/README.md`](v1/README.md)) |
| `TASK.md` | изначальная задача одним файлом, по первоисточникам |

Каждое утверждение в `context/` снабжено ссылкой на источник: `[Онб.10]` — слайд онбординга, `[Разр.14]` — страница лекции по разработке, `[Лек.34]` — слайд лекции по DL, `[12.08 35:18]` — таймкод встречи. Проверяется без перечитывания транскрипций.

**Код — одним git-репозиторием, не четырьмя.** Общие типы (`Schedule`, отклик, `NpvTable`, `RunArtifact`, `Constraints`) нужны всем; в разных репозиториях они либо расходятся копиями, либо требуют публикации версионированного пакета. Сдавать при этом всё равно нужно один репозиторий с логичной структурой и один Docker-образ [Онб.14]. Регистрация в GitLab организаторов, один репозиторий на команду — `context/00_org.md`.

Правила совместной работы над кодом (владение каталогами, контракты, ветки, приёмка) — `aios/CLAUDE.md`; та же карточка обязательна к прочтению любым агентом, работающим в `aios`.
