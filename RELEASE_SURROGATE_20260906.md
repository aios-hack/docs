## Локальный production

Нативная production-сборка запущена на **http://127.0.0.1:18080**. Проверка установленного суррогата доступна по `/data/surrogate-runtime.json` и возвращает `status=ready`. Веб-интерфейс показывает экспортированные данные; этот HTTP-сервер не является API для новых предсказаний. Новые расчёты запускаются через CLI.

Воспроизводимый запуск из корня репозитория:

```bash
AIOS_DOCS_ROOT=/absolute/path/to/docs-with-Model_Z \
AIOS_PYTHON=.venv/bin/python AIOS_PORT=18080 \
  scripts/start-surrogate-production.sh
```

Перед запуском нужны установленное Python-окружение, данные, веса и выполненный `npm run build` в `frontend/`. Скрипт сначала проверяет реальный суррогат, затем запускает сервер готовой статики. Процесс живёт до остановки пользователем/средой; системная служба с автозапуском не устанавливалась.

Dockerfile дополнен ML-зависимостями, Compose — командой `surrogate-check`. **Контейнерная сборка на этой машине не подтверждена:** Docker получил ошибку записи при заполнении диска, после освобождения места его API продолжил отвечать HTTP 500 на `/_ping`. Это состояние относится к первой проверке сборки. Позднее Docker Desktop восстановлен принудительной остановкой и запуском; см. дополнение ниже. Удалённый сервер не обновлялся: адрес и способ доступа не указаны.

## Применение и защита

Полная инструкция, устройство сетей и головы, происхождение 698 исторических расписаний и 833 центров головы, метрики и их ограничения: [SURROGATE_DEFENSE.md](SURROGATE_DEFENSE.md).

Для дальнейшего продвижения новых весов нужны несколько seed, полный train и свежий заранее зафиксированный holdout с оценкой полного бленда и regret короткого списка. Текущий release-пакет сохраняет прежние веса и проверяемую границу области применимости.
