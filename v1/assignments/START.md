# С чего начать — прочитать один раз перед первой задачей

Хакатон AIOS, трек 2. Делаем систему, которая решает, как управлять 103 скважинами на 18 лет вперёд, чтобы заработать максимум денег. Оценивают по одному числу — ЧДД, посчитанному организаторами на нашем расписании. Если их число не сойдётся с нашим — дисквалификация, независимо от качества всего остального.

Работаем с агентами. Ниже — как именно, чтобы не наделать того, что придётся переписывать.

---

## 1. Разложить у себя

Две репы, **обязательно соседними каталогами** — код ищет базу знаний по пути `../docs`:

```bash
mkdir aios-hack && cd aios-hack
git clone https://github.com/aios-hack/docs.git
git clone https://github.com/aios-hack/aios.git
```

Должно получиться так:

```
aios-hack/
├── docs/     ← база знаний: задачи, контракты, разбор модели, материалы организаторов
└── aios/     ← код
```

Установка:

```bash
cd aios
python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"
.venv/bin/pytest contracts/tests
```

**Тридцать зелёных** — всё на месте. Красные — не начинай работу, напиши в чат.

## 3. Открыть сессию агента

**Сессия открывается в `aios`, не в `docs`.**

Не скармливай агенту базу знаний целиком. Дело не только в размере — `08_contracts.md` весит 127 КБ, — а в том, что там лежит **история решений, и часть её описывает отменённое**: каталог отвергнутых вариантов, снятая работа по конвертации дека, журнал с колонкой «было». Агент, прочитавший всё подряд, реализует что-нибудь оттуда и будет выглядеть правым — он же прочитал это в нашей же документации.

Правильный порядок: **своя карточка → типы из `contracts/` → нужный § из docs**, и последний шаг только если контракта не хватило.

Промт — подставить имя и номер задачи, остальное не трогать:

```
Ты работаешь в репозитории aios, сессия <ИМЯ>.

Прочитай CLAUDE.md этого репозитория и следуй ему.
Задача на эту сессию — ровно одна: <НОМЕР> из ../docs/context/09_tasks.md.
Карточка с приёмкой и ловушками — ../docs/assignments/<имя>.md, найди там
строку с этим номером.

Правила сессии:
- работаешь только в своих каталогах, перечисленных в карточке;
- contracts/ не правишь ни при каких условиях: нужна правка типа —
  останавливаешься и говоришь мне, какая именно;
- типы импортируешь из contracts, не переизобретаешь;
- моков нет: не можешь посчитать — NotImplementedError, а не return 0.0;
- приёмка задачи — тест в твоём каталоге, и её содержание написано
  в колонке «Приёмка» карточки, а не придумывается;
- в docs/context/ заходишь только за теми §, на которые ссылается карточка.

Начни с прогона .venv/bin/pytest contracts/tests и скажи, что получилось.

Когда приёмочный тест зелёный и код закоммичен — последним действием
открой ../docs/assignments/order.md, найди строку своей задачи и поставь
в колонку «Статус» значение «готово ДД.ММ · <хеш коммита>». Отдельным
коммитом в репозитории docs с сообщением «задача <НОМЕР> закрыта».
Если теста нет или он красный — ставь «в работе» и скажи мне, что осталось.
```

**Одна сессия — одна задача.** Не «сделай 3, 4 и 5». Задача плюс её приёмка — тот объём, который агент держит без деградации. Следующую — новой сессией.

---

## 4. Правила, которые ломают чужую работу

1. **`contracts/` правит только Савелий.** Это общие типы, на них завязаны все четверо. Не хватает поля — остановись и скажи, какое именно нужно. Подогнать контракт под свой код — самый дорогой способ потратить чужой день.
2. **Пишешь только в своих каталогах.** Даже ради однострочной правки в чужом.
3. **Моков нет.** Не можешь посчитать — `NotImplementedError`. `return 0.0`, `return None` и случайный тензор нужной формы запрещены: они превращаются в правдоподобные числа, которые никто потом не отличит от настоящих.
4. **Ветки `feat/<имя>/<номер-задачи>`**, PR в `main`. Чужие ветки не ребейзить.
5. **Приёмка — тест**, и что он проверяет, написано в карточке, а не придумывается по ходу.

---

## 5. Когда агент сказал «готово»

Тридцать секунд, три проверки:

```bash
cd aios && git diff --stat contracts/ && .venv/bin/pytest
```

- **пустой diff по `contracts/`** — агент не подогнал контракт под свой код;
- **зелёные тесты** — не сломал чужое;
- **глазами:** тест проверяет то, что написано в колонке «Приёмка», а не то, что удобно прошло.

Только после этого статус в `order.md` имеет право стать `готово`.

---

## 6. Три места, где агент напишет правдоподобное и неверное

Типы этого не ловят — контракт задаёт интерфейс, а не логику. Если делаешь экономику, спроси у агента прямым вопросом:

| Как надо | Как он сделает, если не сказать |
|---|---|
| Налог на прибыль считается на **годовой** базе, потом разносится по месяцам | Посчитает помесячно и просуммирует — разойдётся на любом годе с убыточным месяцем |
| Состояние фонда берётся **из отклика симулятора** (`WLPR > 0` или `WWIR > 0`) | Возьмёт из расписания — даст другие событийные затраты |
| Храповик ЭЦН прокручивается **с начала данных**, не с 2007 | Начнёт с 2007 — типоразмер на старте неверен, ошибка уедет во все замены |

Ловит их одна вещь — задача 11, схождение нашего калькулятора ЧДД с эталонным расчётчиком организаторов (`docs/models/CHDD_PYTHON/`). Пока она не закрыта, вся экономика условно верна.

---

## 7. Что важно знать про цифры

- **ЧДД считается эталонным кодом организаторов.** Он лежит у нас: `docs/models/CHDD_PYTHON/`. Расхождение с ним — наш дефект по определению, спорить не о чем.
- **Допуск — «пара процентов»**, и он один на разницу симуляторов и на любую нашу ошибку в экономике. Одна лишняя замена насоса — миллионы рублей, и на численную схему это не спишешь.
- **Расчёт организаторов один, попытка одна**, повторов не предусмотрено.
- **Числа по деку перепроверены 15.08** после того, как организаторы его пересобрали: 371 дата, 225 управляющих шагов при 224 интервалах, 103 скважины. Всё сошлось, контракты синхронизированы.
