1. **Порядок строгий.** Задачи ниже упорядочены по зависимостям. Дошёл докуда дошёл —
   нормально; перепрыгивать нельзя.
2. **Ничего из списка «не трогать»** (в конце документа). Там лежат решения, которые
   принимает человек, а не исполнитель.
3. **Не запускать OPM, Docker и полный `pytest`.** Прогонять только группы, которых касаешься:
   `pytest tests backend/core/contracts/tests backend/domain/schedule/tests` и т. п. Полный прогон

4. **Не менять числа** (`BASE_NPV`, значения в `config/*.json`, содержимое
   `frontend/public/data/`), не трогать `data/`.

7. Если задача упирается в отсутствующий артефакт (веса суррогата, прогон OPM) — **пропустить**
   и записать причину в конце ветки одним файлом `NIGHT_REPORT.md`.
